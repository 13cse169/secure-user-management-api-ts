Overview / Phase 3

Phase 3: PostgreSQL database setup

We replace the in-memory array in user.service.ts with PostgreSQL, a relational database suited to our user management API.

Goal

Connect the API to PostgreSQL.

Deliverable

A working database with a users table, queried by the API through pg.

Why

Why do we need a database?

Our current service stores users in a JavaScript array:

src/services/user.service.ts (current)
const users: User[] = [
  { id: 1, name: "Birendra Singh", email: "birendra@example.com" },
  { id: 2, name: "Rahul Sharma", email: "rahul@example.com" }
];

The array has several limitations

  • Data disappears. Restarting the server resets the array.
  • No real persistence. We can’t reliably store thousands of users.
  • No database security. We can’t enforce unique email addresses through database constraints.
  • Limited querying. Searching, filtering, and managing users becomes harder as the application grows.
3.1

Verify PostgreSQL is running

1. Check the version

Open your terminal (in VS Code, the integrated terminal) and run:

Terminal
psql --version
Expected output (your version may differ; that’s fine)
psql (PostgreSQL) 17.x

Saw a version number?

Continue to the next check.

“psql is not recognized”?

PostgreSQL may still be installed, but its bin directory might not be in your Windows PATH. Don’t reinstall yet. Go to Step 3.2.

2. Check whether you can connect

Terminal
psql -U postgres -h localhost

Enter your PostgreSQL password if prompted. The password won’t appear as you type. If the connection succeeds you’ll see a prompt like this:

psql prompt
postgres=#

Type this command to exit:

psql
\q
3.2

If you get a connection error, find your installation

Only follow this step if 3.1 failed with an authentication or connection error, or psql wasn’t recognized.

1. Check the installation folder

Open File Explorer and go to C:\Program Files\PostgreSQL\. You might see a folder such as C:\Program Files\PostgreSQL\17\. Inside it, look for the bin folder:

C:\Program Files\PostgreSQL\17\bin\

Your version number might be different, such as 16, 17, or 18.

2. Check whether psql.exe exists

Inside the bin folder, look for psql.exe. If you find it, open your VS Code terminal and run this command, replacing 17 with your installed version:

PowerShell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" --version
Example output
psql (PostgreSQL) 17.6

3. Connect to PostgreSQL

If the version command works, run:

PowerShell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -h localhost -p 5432

Enter your PostgreSQL password when prompted. If successful, you’ll see postgres=#, which means you’re connected to the PostgreSQL database server. To exit, type \q.

3.6

Create the database connection

1. Create the configuration folder

Inside src, create a folder named config and add the file src/config/db.ts. Your structure should now look like this:

src/
config/
db.ts
controllers/
middlewares/
routes/
services/
app.ts
server.ts

2. Add the connection pool code

src/config/db.ts
import pg from "pg";
import "dotenv/config";

const { Pool } = pg;

const pool = new Pool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT) || 5432,
  database: process.env.DB_NAME,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
});

export default pool;

3. Understand the code

PartMeaning
PoolManages a collection of reusable database connections
hostWhere PostgreSQL is running. Here, your own computer (localhost)
portUsually 5432, the default PostgreSQL port
databaseSelects our secure_user_management database
user, passwordThe PostgreSQL credentials from .env
export default poolLets other files import and use this connection pool
Why use a pool?

If 100 requests arrive, we don’t want to open 100 new database connections. The pool reuses connections and limits how many can be active at once.

3.8

Create the users table

1. Connect to your project database

Open your PostgreSQL terminal and connect:

psql
\c secure_user_management

Make sure the prompt shows secure_user_management=#.

2. Create the users table

SQL
CREATE TABLE users (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL,
  password_hash TEXT NOT NULL,
  is_email_verified BOOLEAN NOT NULL DEFAULT FALSE,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  CONSTRAINT users_name_not_empty
    CHECK (LENGTH(TRIM(name)) > 0),

  CONSTRAINT users_email_not_empty
    CHECK (LENGTH(TRIM(email)) > 0)
);

CREATE UNIQUE INDEX users_email_unique_idx
ON users (LOWER(email));
Expected output
CREATE TABLE
CREATE INDEX

3. Understand the columns

ColumnPurpose
idUnique ID for every user
nameUser’s full name
emailUser’s email address
password_hashStores the hashed password, never the original password
is_email_verifiedTracks email verification status
is_activeAllows admins to deactivate users
created_atAccount creation timestamp
updated_atLast update timestamp

A few important decisions

Identity column

BIGINT GENERATED ALWAYS AS IDENTITY automatically generates user IDs.

Primary key

PRIMARY KEY ensures every user has a unique ID.

Case-insensitive unique email

The unique index on LOWER(email) prevents duplicate emails even when their casing differs. User@gmail.com and user@gmail.com can’t both be registered.

TIMESTAMPTZ

Stores timestamps with timezone awareness.

Security note

We will hash passwords before saving them. We will never store plain-text passwords.

4. Verify the table

psql
\d users

This displays the table structure. Then run:

psql
SELECT * FROM users;

It should return an empty result because we haven’t registered any users yet.

3.9

Fetch users from PostgreSQL

1. Create a TypeScript user type

src/types/user.types.ts
export type User = {
  id: string;
  name: string;
  email: string;
  is_email_verified: boolean;
  is_active: boolean;
  created_at: Date;
  updated_at: Date;
};
Why is id a string?

PostgreSQL BIGINT values can exceed JavaScript’s safe integer range. The pg driver normally returns BIGINT as a string, so we represent it as a string in TypeScript.

2. Update the user service

Open src/services/user.service.ts and replace the existing code with:

src/services/user.service.ts
import pool from "../config/db.js";
import type { User } from "../types/user.types.js";

export const getAllUsers = async (): Promise<User[]> => {
  const result = await pool.query<User>(
    `SELECT
      id,
      name,
      email,
      is_email_verified,
      is_active,
      created_at,
      updated_at
    FROM users
    ORDER BY id ASC`
  );

  return result.rows;
};

We’re no longer using a JavaScript array. We’re executing an actual SQL query.

Why not SELECT *?

We explicitly select columns instead of SELECT * so we don’t accidentally expose password_hash through our API.

3. Update the user controller

Our service now returns a Promise because database queries are asynchronous, so the controller must become asynchronous too. Open src/controllers/user.controller.ts and replace its code with:

src/controllers/user.controller.ts
import type { Request, Response, NextFunction } from "express";
import { getAllUsers } from "../services/user.service.js";
import { sendResponse } from "../utils/api-response.js";

export const getUsers = async (
  _req: Request,
  res: Response,
  next: NextFunction
): Promise<void> => {
  try {
    const users = await getAllUsers();

    sendResponse(
      res,
      200,
      "Users fetched successfully",
      users
    );
  } catch (error) {
    next(error);
  }
};

Understand the important changes

  1. Why async? Because our database query takes time to execute.
  2. Why await getAllUsers()? It waits for PostgreSQL to return the records before sending the response.
  3. Why try/catch? Database operations can fail: the server may be unavailable, the connection pool may be exhausted, or the SQL query may contain an error.
  4. Why next(error)? It forwards the error to our existing global error-handling middleware, so we don’t format database errors separately in every controller.
