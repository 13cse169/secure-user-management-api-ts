Overview / Phase 1

Phase 1: Project setup and TypeScript fundamentals

Now we begin the actual project: Secure User Management API.

For now we won’t implement JWT, email verification, or admin permissions. First we create a clean project structure and make sure TypeScript and Express work correctly. If the basic setup is wrong, debugging later authentication and database problems becomes unnecessarily difficult.

Goal

Create a working Express server using TypeScript.

Deliverable

A working TypeScript API with a health-check endpoint.

  • Node.js, TypeScript and Express together
  • npm project
  • tsconfig.json
  • Environment variables
  • Files and folders
  • Git
1.1

Check your installed software

Open your terminal in VS Code and execute:

Terminal
node -v
npm -v
git --version

You should see version numbers for Node.js, npm, and Git.

PostgreSQL can wait

If you haven’t installed PostgreSQL yet, we’ll install it before the database phase. You don’t need to configure it during this first step.

1.2

Create the project

Run:

Terminal
mkdir secure-user-management-api
cd secure-user-management-api

Initialize npm:

Terminal
npm init -y

This creates package.json, which records the project’s dependencies, metadata, and scripts.

Install the initial dependencies:

Terminal
npm install express dotenv

Install TypeScript and development tools:

Terminal
npm install -D typescript tsx @types/node @types/express

Why do we need these packages?

PackageExplanation
expressCreates our HTTP server and API routes
dotenvLoads environment variables from .env
typescriptChecks and compiles TypeScript
tsxRuns TypeScript during development
@types/nodeProvides TypeScript definitions for Node.js
@types/expressProvides TypeScript definitions for Express

We’re keeping the initial dependencies small. PostgreSQL, JWT, password hashing, validation, and email packages come in the corresponding phases.

1.3

Configure TypeScript

Run:

Terminal
npx tsc --init

This creates a tsconfig.json file. Replace its contents with:

tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "noEmitOnError": true
  },
  "include": ["src/**/*.ts"],
  "exclude": ["node_modules", "dist"]
}

Let’s understand the important settings

SettingMeaning
targetJavaScript language version for the compiled output
moduleUses Node.js’s native ES module conventions
moduleResolutionResolves imports according to Node.js module rules
rootDirLocation of our TypeScript source files
outDirLocation of compiled JavaScript
strictEnables stricter type checking
esModuleInteropHelps with compatibility when importing certain CommonJS packages
noEmitOnErrorPrevents emitting output when TypeScript compilation fails
Important

Because we’re using NodeNext, we also configure the project for ES modules. That affects how we write imports and exports.

1.4

Update package.json

Add "type": "module" and configure the scripts. Your package.json should contain these fields alongside the metadata and dependencies npm created:

package.json
{
  "type": "module",
  "scripts": {
    "dev": "tsx watch src/server.ts",
    "build": "tsc",
    "start": "node dist/server.js"
  }
}
Don’t replace the whole file

Keep the existing fields and dependencies. Only update the type and scripts fields.

We now have three commands

CommandWhat it does
npm run devStarts the development server and watches for changes
npm run buildCompiles TypeScript into JavaScript
npm startRuns the compiled application

1.6

Create src/app.ts

Add the following code:

src/app.ts
import express from "express";

const app = express();

app.use(express.json());

app.get("/api/health", (_req, res) => {
  res.status(200).json({
    success: true,
    message: "Secure User Management API is running"
  });
});

export default app;

Understand this code

1. Import Express
import express from "express";

This imports Express so we can create an API application.

2. Create the application
const app = express();

This creates our Express application.

3. Add JSON middleware
app.use(express.json());

This allows Express to parse incoming JSON request bodies. Without it, req.body generally won’t contain the parsed JSON data we expect.

4. Create a health-check route
app.get("/api/health", (_req, res) => {
  res.status(200).json({
    success: true,
    message: "Secure User Management API is running"
  });
});

This endpoint lets us check whether the API is responding. The underscore in _req indicates that we’re not using the request parameter in this handler.

5. Export the application
export default app;

We export the application so another file can start the HTTP server.

Why separate app and server?

This separation will become useful when we write automated tests.

1.7

Create src/server.ts

Add:

src/server.ts
import "dotenv/config";

import app from "./app.js";

const PORT = Number(process.env.PORT) || 3000;

app.listen(PORT, () => {
  console.log(`Server is running on port ${PORT}`);
});

Notice this import:

import app from "./app.js";
Yes, it’s .js, not .ts

Even though the source file is named app.ts, the .js extension is correct for this NodeNext ES-module setup. TypeScript resolves the source file during development and emits app.js during compilation.

We’ll explore ES modules in more detail as we progress.

1.8

Create the .env file

Add:

.env
PORT=3000
NODE_ENV=development

Environment variables let us configure the application without hardcoding every setting into our source code. Later we’ll add database connection settings and authentication secrets.

Never commit real secrets

Don’t commit real passwords, JWT secrets, API keys, or email credentials to GitHub.

1.9

Create .gitignore

Add:

.gitignore
node_modules/
dist/
.env
coverage/

This prevents Git from tracking installed dependencies, compiled output, local environment secrets, and test coverage artifacts.

Coming later

We’ll commit a .env.example containing placeholder values instead of real secrets, so someone cloning the project knows which environment variables to configure.

1.10

Run the project

In your terminal:

Terminal
npm run dev

You should see:

Output
Server is running on port 3000

Open this endpoint in your browser, and you should get the expected response:

http://localhost:3000/api/health
{
  "success": true,
  "message": "Secure User Management API is running"
}

Now test the TypeScript build:

Terminal
npm run build

If everything is configured correctly, TypeScript compiles the files into the dist folder.

1.11

Your first Git commit

Once the server and build both work, initialize Git:

Terminal
git init
git add .
git status
Check before committing

Make sure .env and node_modules are not included in the staged files.

Then commit:

Terminal
git commit -m "Initial TypeScript Express API setup"

If Git asks you to configure your identity, set your Git username and email before committing. We can connect the repository to GitHub after this initial setup works.

Phase 1 complete?

You should now have a TypeScript Express API that runs in development, builds to dist, answers on /api/health, and has its first commit.
